# 01 · 表格标准样式 SOP（辰微三系统）

> **这份文件是什么**：三个系统（生产排单 / 质量 / 管理员后台）里所有"表格页"的**统一施工标准**。
> 新建一张表、给已有表加一列、改列布局/合计/悬浮/吸附——**先读这里，再动手**。

> **口径真源**：本文件与代码冲突时**以代码与测试为准**，并应立即修正本文件。
> 本文引用代码位置一律写「文件 · 函数名」，**不写行号**（行号随每次改动腐化，这是 `00-铁律速查` 明确记过的教训）。

## §2 名词与五层模型

**这章解决什么问题**：把"表格"拆成互不越界的五层，**任何改动先定位到层**，才能回答"改这里要连带改什么"。

### 表2-1 五层定义

| 层 | 名称 | 唯一职责 | 输入 | 输出 | 档位 |
|---|---|---|---|---|---|
| **L1** | 结构层（DOM 骨架） | 物理骨架与容器职责，**禁含业务逻辑** | 列数 N | `bulkBar → filterBar → .sticky-head(.head-scroll>table.head-tbl>colgroup+thead) → .table-wrap>table.body-tbl>colgroup+tbody(+合计行)`；空态分支 | 基础：`bulkBar`/`filterBar`/`.table-wrap`/`thead`+`tbody`/空态<br>增强：`colgroup` / `.sticky-head` / `.head-scroll` / `head-tbl`+`body-tbl` 双表 / `.bottom-scrollbar` |
| **L2** | 数据契约层（列定义 schema） | **全工程唯一一份**列定义 | 业务字段清单 | `TBL_SCHEMAS[m]` / `QA_COLUMNS` | 基础：`key`+`label`+`type`+`get`，消费方**禁止硬编码列名** |
| **L3** | 交互引擎层 | 三态排序、模式筛选、切片分页、选择集；**判据必须单源** | schema + rows + 视图状态 | 可见行集合 + 分页窗口 + chips + 漏斗点亮态 | 基础：排序/筛选/分页/回第 1 页/勾选一致性/空态 |
| **L4** | 列布局层 | 列的身份与呈现顺序的唯一裁判 | DOM 表头 + 布局存储 | 重排后的行 + 落盘的 `{order, widths}` | 【增强·整层可选】 |
| **L5** | 呈现增强层 | 只做"看得见"的增强，**不得改变 L3 的判定结果** | 可见行集合 + DOM 尺寸 | 合计行 / 深色 tip / 吸附位置 / 滚动复位 | 【增强·整层可选】 |
| **L6'** | 各系统自填 | 系统间**只允许**在这 6 处不同 | — | — | ①模块 key（`order_frame` / `qaLog`）②列定义内容 ③权限门控口径 ④本地存储前缀与键名 ⑤导出列与业务动作按钮 ⑥每页条数默认值 |

### 表2-2 层间依赖（禁止逆向）

| 允许 | 说明 |
|---|---|
| L5 → L4 → L3 → L2 → L1（**只能向下**） | 呈现层可以读引擎结果，引擎可以读 schema，schema 可被结构层渲染 |
| L1 不得读写任何数据 | 骨架是纯字符串拼接，出现"业务字段名"即越界 |
| L3 不得直接读 DOM 尺寸 | 排序/筛选结果必须能脱 DOM 单测（质量系统 `qa-core.js` 即此纪律的产物） |
| **L5 不得反算 L3** | 合计行不得自己"再算一遍筛选"——必须接收 L3 已筛好的集合 |
| L4 不得改写 L2 顺序 | 拖拽只改"呈现顺序"，不得改 `QA_COLUMNS` / `TBL_SCHEMAS` 里的定义顺序 |

> **违反后表现为**：某天发现"同一个筛选条件下，表格行数与合计对不上"——几乎必然是 L5 自己算了一遍。

## §3 【基础】DOM 骨架与类名契约

**这章解决什么问题**：所有表格长得一样、滚起来一样、坏起来一样。骨架和类名是唯一的"物理契约"。

### 表3-1 骨架元素表（自上而下，顺序固定）

| # | 元素 | 必需 class / 属性 | 是否必需 | 说明 |
|---|---|---|---|---|
| 1 | 操作栏容器 | `.bulk-bar` | **必需** | 全选/增删改/业务动作/已选计数/右侧分页器 |
| 2 | 筛选状态条 | `.tbl-fbar` | 有筛选能力时必需 | 无生效筛选返回空串（不占位） |
| 3 | 吸附表头容器 | `.sticky-head` | 【增强】 | **div sticky**，不用 `thead{position:sticky}`（见 §11.3） |
| 4 | 表头横向滚动容器 | `.head-scroll` | 【增强】 | 表体横滚时由 capture 委托同步 `scrollLeft` |
| 5 | 表头表 | `table.head-tbl` | 【增强】 | 只含 `colgroup` + `thead`，**不含 tbody** |
| 6 | 列宽定义 | `colgroup > col × N` | 【增强】 | **表头表与表体表各带一份**，两表列数必须相同 |
| 7 | 表体容器 | `.table-wrap` | **必需** | `overflow-x:auto`；启用底部固定横滚条时必须 `scrollbar-width:none` |
| 8 | 表体表 | `table.body-tbl` | 【增强】 | 含 `colgroup` + `tbody`；**承载 rowspan 合并** |
| 9 | 勾选列表头/单元格 | `.sel-col` | 有勾选时必需 | 左吸附列，`position:sticky;left:0` |
| 10 | 合计行 | `tr.sum-row`（表体表 `</tbody>` 之前） | 【增强】 | **不用 `<tfoot>`**（见 §12） |
| 11 | 底部固定横滚条 | `#bottomScrollbar > #bottomScrollbarInner` | 【增强】 | 页面级 fixed，不随表格滚动位移 |
| 12 | 悬浮提示容器 | `.cell-tip`（`body` 下唯一一个） | 【增强】 | 全站**唯一** tooltip，禁止再用原生 `title` |

> **数量口径**：`colN = 1（勾选列）+ 列定义条数`。两表列数不一致 ⇒ 不是"差一点"，是**逐列偏移**。

### 表3-2 类名契约（改它要同时改谁）

| 类名 | 职责 | 所属层 | **改它要同时改谁** |
|---|---|---|---|
| `.sticky-head` | 吸附容器与"表体前一个兄弟"的定位锚 | L1 | `fixStickyHeadTop()`、`syncHeadBody()`、`applyTableLayout()`、滚动跟随委托、`startColResize()`（它靠 `closest('.sticky-head')` 找表体） |
| `.head-scroll` | 表头横向滚动 | L1 | 滚动跟随委托（`scrollLeft` 同步）、`restoreTableScroll()` 的滚动位记录选择器 |
| `table.head-tbl` / `table.body-tbl` | 双表本体 | L1 | `syncHeadBody()`、`applyTableLayout()`（两表都要重排）、`startColResize()` 的实时同步 |
| `.table-wrap` | 表体滚动容器 | L1 | `syncBottomScrollbar()`、`bindTableScrollFollow()`、原生横条隐藏规则 |
| `tr.sum-row` / 合计行 `td` | 合计 | L5 | `sumRowHtml()`、`applyTableLayout()`（合计行 `td` **必须带列身份属性**才能跟着重排） |
| `th.th-sort` | 可排序表头 | L1+L3 | `sortTh()`/`thCol()`、`bindColInteractions()`（mousedown 委托只认它）、`applyTableLayout()` |
| `.th-flex` / `.th-label` | 表头内布局与文本 | L1 | `minThWidth()`（用 `.th-label` 量首字宽）、cell-tip（`.th-label` 也算可悬浮） |
| `.sort-ico` | 三态箭头 `▲▼⇅` | L3 | `minThWidth()` 的 `sortW` 常量与 `9px` 字号必须与 CSS 一致 |
| `.filt-ico` | 漏斗图标与点亮态 | L3 | `filtOn()`/`isSemFiltMode()`（点亮判据）、`startColDrag()`（**必须排除**，否则从漏斗开始拖列） |
| `.th-rs` | 列宽拖拽手柄 | L4 | `bindColInteractions()`（手柄优先于拖序）、`th.th-sort{position:relative}`（缺了手柄飞到页面右上角） |
| `.th-dragging` / `.th-drop-before` / `.th-drop-after` | 拖序视觉 | L4 | `startColDrag()` 的清理逻辑（每次 move 先清旧指示） |
| `.row-sel` / `.row-flash` | 行选中 / 保存后闪一下 | L3+L5 | `updateSelUI()`、行内局部刷新 |
| `.cell-tip` | 悬浮提示 | L5 | `bindCellTip()`；**与 `.col-clip` 的 ellipsis 配套**（不截断就永远不弹） |
| `.bottom-scrollbar` | 底部横滚条 | L5 | `syncBottomScrollbar()`、滚动跟随委托的双向同步 |

## §4 【基础】列定义 schema 字段字典

**这章解决什么问题**：加一列**只改一处**。凡出现"表头有了但 CSV/表单/合计没有"，都是有人绕过了 schema。

### 表4-1 字段字典

**生产系统（`TBL_SCHEMAS[m]`，行模型为 `{order,item,orderIdx,__li}` 包装对象）**

| 字段 | 类型 | 必填 | 默认 | 消费方 | 缺失行为 |
|---|---|---|---|---|---|
| `key` | string | **是** | — | 全部 | 列无法被定位，`applyTableLayout` 跳过该列 |
| `label` | string | **是** | — | 表头 / chips / 筛选面板标题 / CSV | 显示空白 |
| `type` | `'text'\|'number'\|'date'` | **是** | `'text'` | 比较器、筛选分支、合计范围、右对齐 | 当文本处理（数值排序会变字典序） |
| `get` | `(row)=>any` | 否 | 直取 `r[key]` | 取值单点（`colVal`） | 取不到 ⇒ 空串（不报错） |
| `select` + `options` | boolean + array | 否 | — | 筛选面板改**复选多选**（`vals`, mode=`in`） | 退回文本模式 |
| `sort` | `(v)=>number` | 否 | — | 排序改"语义权重"（如状态机顺序） | 按 `type` 常规比较 |
| `locked` | boolean | 否 | — | 表头显示锁图标；`minThWidth` 多留 18px | 无锁标识 |
| `semFilters` | `[{mode,label,test}]` | 否 | — | 列级语义档（如"低于最小库存量"）：命中后**只按行级 `test(r)` 判定**，与列值无关 | 面板不出现该档 |

**质量系统（`QA_COLUMNS`，行模型为扁平记录）**

| 字段 | 类型 | 必填 | 默认 | 消费方 | 缺失行为 |
|---|---|---|---|---|---|
| `key` / `label` / `type` | 同上 | **是** | — | 同上 | 同上 |
| `sortable` | boolean | 否 | falsy | 排序白名单（`sortBy` 直接拒绝非白名单列） | 该列不可排序、不渲染漏斗 |
| `inTable` | boolean | 否 | falsy | 是否占列表列（`tableCols()`） | 只在表单出现，不进表格/CSV |
| `formKind` | `'date'\|'readonly'\|'text'\|'number'\|'textarea'` | 否 | — | 表单控件类型；`readonly` ⇒ **不进请求体** | 不上表单 |
| `formRow` | number | 否 | — | 表单分行（同号并排） | 独占一行 |
| `required` | boolean | 否 | falsy | 后端必填校验 + 表单 `*` | 可空 |
| `hint` | string | 否 | — | 字段下方灰字（编号列提示"保存后自动生成"） | 无提示 |
| `filterType` | `'text'\|'num'\|'date'` | 否 | 由 `type` 推导 | **目前无消费方**（模式档实际读 `type`）⇒ 🔜 **D16** | 无影响 |

> ⚠ `filterType` 是**已文档化但未消费**的字段（🔜 D16）。要启用它，须把 `CORE.filtModesOf(col.type)` 改成读 `col.filterType||col.type`，
> 并同步 `CORE.matchFilter` 的分支口径——**两处一起改**，否则面板给的模式与判定分支不一致
> （症状：选了某模式但表格纹丝不动，与 `.161` 判据分叉同族）。**只改一处**是明令禁止的做法。

### 表4-2 消费方清单（每行都必须由 schema 派生）

| 消费方 | 生产 | 质量 | 硬要求 |
|---|---|---|---|
| 表头 | `thCol(m,col)` | `sortTh(col)` | 禁止出现 `sortTh('字面量')`（质量侧有变异守卫钉住） |
| 表体单元格 | 行渲染分支 | `cellHtml(col,rec)` | 每格必须带**列身份属性**（见下） |
| CSV / 导出 | 按 schema 取 `get` | `CORE.buildCsv(rows, tableCols())` | 禁止手写 `label` 字面量 |
| 表单 | 按 `fields.*` 派生 | `formFieldHtml` + `formCols()` | 字段 id 统一 `qa_f_<key>` |
| 合计行 | `sumRowHtml(schema,…)` | `sumRowHtml(rows)` | 禁手写求和列名，用 `sumColKeys()` |
| 筛选面板 | `openFilter` 读 `col.type/semFilters` | `openFilter` 读 `CORE.filtModesOf(col.type)` | 模式清单不得写在 UI 层 |
| 排序白名单 | `sortRows` 按 `col` 找 `TBL_SCHEMAS` | `sortBy` 判 `col.sortable` | — |
| 行内局部更新 | 按 `data-key` 定位 | `applyRowUpdate` 按 `data-col` 定位 | **禁止 `tds[1]` 下标定位**（加一列即静默错位） |
| 布局归一化 | `applyTableLayout` | `normalizeLayout()` | 存储里出现**未知列 key** ⇒ 剔除（列已删/手工改过） |

### 4.3 列身份属性：两系统**唯一必须不同**的地方

| 系统 | 列身份属性 | 位置 | 为什么不能换 |
|---|---|---|---|
| 生产 | **`data-key`** | `thCol` 的 `th`、数据行与合计行的 `td` | 既有拖拽/合计/`applyTableLayout` 全靠它，改它 = 全表错列 |
| 质量 | **`data-col`** | `sortTh` 的 `th`、`cellHtml` 的 `td`、合计行 `td` | `qa.ledger-fields §B2` 已把 `data-col` 钉死（行内更新精确定位） |

> **强制**：同一系统内**只许一种**。两套并存必然在双表结构（表头表 / 表体表）里错位。
> **违反后表现为**：拖一次列，表头顺序变了、表体没变，从此整表错列且刷新也不恢复。

## §5 【基础】表头三件套（排序图标 / 漏斗 / 拖宽手柄）

**这章解决什么问题**：表头是用户唯一能"操作表格"的入口，三件套的尺寸、事件、冒泡必须三系统一致。

### 表5-1 三件套规格

| 件 | 元素与 class | 触发事件 | 必须 `stopPropagation` | `title` 文案 | 备注 |
|---|---|---|---|---|---|
| 排序 | `th.th-sort` > `.th-flex` > `.sort-ico` | `th` 的 `click` → `toggleSort` / `sortBy` | 否（图标是视觉，不独立响应） | — | 三态：升 → 降 → 取消 |
| 漏斗 | `.filt-ico`（内含 `FILT_SVG`） | `click` → `openFilter` / `QA_APP.openFilter` | **是**（否则点漏斗顺带排序） | `筛选` | 12×12 行内尺寸，与生产逐字节一致 |
| 拖宽 | `.th-rs`（绝对定位 `right:0`，宽 7px） | `mousedown` → `startColResize` | **是**（`preventDefault` + `stopPropagation`） | `拖动调整列宽` | `th.th-sort{position:relative}` 为定位基准 |

- 表头点击的**统一入口**是 `mousedown` 委托（`bindColInteractions` / 生产同名委托）：手柄 → 调宽；`.filt-ico` → **不启动任何拖拽**；其余 → 拖序。
- 排序点击必须受 **350ms 拖拽抑制**（`window.__colDragTS`）：拖完列紧跟一次 `click`，不拦就会"顺手把排序也改了"。

### 表5-2 最小列宽算式（`minThWidth`）

拖到最窄时列名还能读：**第一个字 + `..` + 排序符号 + 漏斗 + padding**。

| 项 | 常量 | 来源 |
|---|---|---|
| `firstW` | 列名首字符宽度 | canvas `measureText(标签.charAt(0))`，字体取 `getComputedStyle(th)` |
| `dotsW` | `'..'` 宽度 | 同上（省略号） |
| `sortW` | `⇅` 宽度 + `3` | 字号按 **9px**（与 `.sort-ico` 一致）；量不出时兜底 `9`；`+3` = `.sort-ico` 左距 |
| 筛选图标 | `19` | `12`(图标) + `5`(左距) + `2`(padding) |
| th padding | `20` | 左右各 10 |
| 余量 | `4` | — |
| 锁定角标 | `+18` | **仅生产**（有 `locked` 字段）；质量系统无锁定列，**必须删掉这一项**，否则每列白宽 18px |
| 兜底 | `60` | `measureText` 抛错时（环境不支持 canvas） |

> **禁止**把最小宽写成固定值（如 80px）：中文列名 1 个字与 6 个字需要的宽度差数倍。
> **违反后表现为**：某些列拖窄后，列名被截成空白或 `⇅`/漏斗被吃掉一半。

## §6 【基础】排序与筛选引擎

**这章解决什么问题**：排序/筛选是最容易被"各写一份"侵蚀的地方——历史上三次缺陷（`.161`/`.162`/D11）全是**同一条判据的多份副本只改了一处**。

### 表6-1 排序口径（四分支）

| `type` / 自定义 | 比较方式 | 空值策略 | 依据 |
|---|---|---|---|
| `sort` 函数存在 | `(sort(va) - sort(vb)) * dir` | 由函数决定 | 语义权重（状态机顺序等），**优先级最高** |
| `number` | `(num(va) - num(vb)) * dir` | 生产：`Number('')=0` ⇒ 空值被当 0，升序排最前 | 生产 `cmpByColDef` |
| `date` | `fmtDate` 后字典序，`va<vb ? -dir : …` | 空串最小 | 同上 |
| `text` | `localeCompare(vb,'zh-CN') * dir` | 空串最小 | 中文按拼音，**不要**用 `<` 直接比字符串 |

**唯一刻意的系统差异**：质量系统的 `CORE.sortRecords` **空值恒沉底**（不随升降翻转）。
理由：台账数量列经常整列空着（未检测就登记），若沿用 `Number('')=0`，升序时一排空值糊在表头下面＝把"未填"误报成"最少"。
> **新增系统时二选一并写进注释**：本表是"业务表（数量列几乎不为空）"用生产口径，"登记表（大量空值）"用质量口径。

### 表6-2 筛选模式清单

| 列类型 | 模式 | 值来源 | 生效判据 |
|---|---|---|---|
| 文本 | 文本 8：`contains` / `not_contains` / `eq` / `neq` / `startswith` / `endswith` / `is_empty` / `not_empty` | `val`（前 6 个）/ 无值（后 2 个） | `filtOn` |
| 数字（生产） | 4：`gte` / `lte` / `eq` / `neq` | `val` | `filtOn` |
| 数字（质量） | 6：生产 4 + `is_empty` / `not_empty` | 同上 | `CORE.filtActive` |
| 日期 | 8 快捷：`today` / `this_week` / `this_month` / `last_month` / `last_1m` / `last_3m` / `range` / `eq` | 前 7 个无值（`range` 用 `from`/`to`）/ `eq` 用 `val` | `filtOn`（`range` **首判** `from && to`） |
| select 类列 | 复选多选（`vals` + `mode='in'`） | `vals` 数组 | 非空即生效 |
| 列级语义档 | `semFilters:[{mode,label,test}]`（如"低于最小库存量"） | 无值，**行级 `test(r)`** | `isSemFiltMode(m,key,mode)` |

**`range` 必须首判**：它的取值在 `from`/`to` 而非 `val`，若落到下面"零值自由模式"那一支，空区间会被判为"生效"
⇒ 用户点了确定、chip 出现、漏斗点亮，但表格纹丝不动。质量系统曾栽过此坑。

### 表6-3 判据单源调用图（D11 修复后）

```
                    ┌─────────────────────────── 判据三兄弟（唯一来源）──────────────────────────┐
                    │ isValFreeFiltMode(f)   ← 该模式 val 恒空？                                 │
                    │   = is_empty ∨ not_empty ∨ dateQuickMode(7 档含 range)                     │
                    │ filtOn(f)              ← 该条筛选是否生效？                                 │
                    │   = range ? (from&&to) : (vals 非空 ∨ val 非空 ∨ isValFreeFiltMode(f))      │
                    │ isSemFiltMode(m,key,mode) ← 该模式是否为**本列声明**的语义档？（需列信息）   │
                    └───────────────────────────────────────────────────────────────────────────┘
                                            │
        ┌────────────────┬──────────────────┼──────────────────┬────────────────────────┐
        ▼                ▼                  ▼                  ▼                        ▼
   filterRows        thCol 漏斗点亮      filterBar chip 放行   prodFilterActive      maybeWarnHiddenOrder
 （filtOn ∨ !!sem）  （filtOn ∨ sem）   （filtOn ∨ sem）      （filtOn）             （filtOn）
```

| 消费方 | 生产 | 质量 | 说明 |
|---|---|---|---|
| 引擎闸门 | `filterRows`：`isValFreeFiltMode(f) || !!sem` | `CORE.applyFilters` 内部用 `filtActive` | 语义档需列信息 ⇒ 由调用处补 `!!sem` |
| 漏斗点亮 | `thCol`：`f && (filtOn(f) \|\| isSemFiltMode(...))` | `sortTh`：`CORE.filtActive(state.filters[key])` | **D11 的修复点** |
| chip 放行 | `filterBar`（`semModeOf` 是委托别名） | `filterBarHtml` 用 `filtActive` | — |
| 拖拽禁用 | `prodFilterActive` | — | 产品主数据长按拖行在有筛选时禁用 |
| 保存后提示 | `maybeWarnHiddenOrder` | — | 行被筛掉时提示"已保存但看不到" |

> **D14（未修，已登记）**：产品选择浮层 `ppTh` / `ppUpdateHeader`（状态在 `window.__ppFilterState`）仍是第 6/7 份副本。
> 该浮层只提供复选 / 文本 3 模式 / 数字 4 模式，**不提供 `is_empty` 与日期模式** ⇒ D11 不可达，本轮有意不动。
> **新增筛选能力时先收敛这两处**，否则会立刻复现 `.161` 那类"只改一处"的缺陷。
>
> **禁止**：为了少传一个参数，把 `key`/`schema` 塞进 `filtOn`。列级语义档必须由调用处用 `isSemFiltMode` 补——
> 一旦把列信息塞进去，就会造出第二套判据。

## §8 【基础】空状态与错误态

**这章解决什么问题**：空表最容易被敷衍成一句"暂无数据"，而用户看到的"空"至少有四种完全不同的原因。

### 表8-1 四态

| 态 | 触发条件 | 文案要求 | 图标 | **必须提供的出口** | 禁止文案 |
|---|---|---|---|---|---|
| 真无数据 | 库里确实 0 条 | 「暂无异常记录」/「暂无订单」——说清"哪个东西"没有 | 列表类图标 | **有写权限时**提供「新增」按钮 | 「加载失败」「无数据」这类含糊话 |
| 筛空 | 有生效筛选但 0 命中 | 「当前筛选条件下没有匹配的记录」 | 列表类图标 | **必须**提供「清除全部筛选」 | 「暂无数据」（会让用户以为数据被删了） |
| 加载中 | 请求进行中 | 「加载中…」 | — | 不需 | 空表 + 无提示（用户会反复点刷新） |
| 请求失败 | 非 2xx / 网络失败 | 服务端中文消息；鉴权类（503）用**顶部非阻塞提示条**+「重试」+自动重试一次 | — | 「重试」/<br>401 ⇒ 登录卡片 | 静默失败、`alert('undefined')` |

**现状差异**：质量系统已实现四态（`emptyHtml` / `noMatchHtml` / 登录卡片 / `qa-notice` 提示条 + 503 fail-closed）。
生产系统目前把"真无数据"与"筛空"合并为一态（`noMatchRow`，文案"无匹配数据"+清除筛选入口）——**不违规但不理想**，
新表按本表区分两态；生产侧改造登记为后续可选项。

> **违反后表现为**：用户打电话问"是不是把我的数据清了"——99% 是把"筛空"写成了"暂无数据"。

## §9 【强制】唯一标识（主键）契约

> **这章解决什么问题**：用户原话——「建立表单时需要明确哪一项是唯一标识，在后续可能存在的下推、调用功能中很关键」。
> 这张表的主键会被下游引用（下推、调用、报工回写、对账），**主键设计错，错的是整条业务链**。
> **谁必须读**：任何新建表单/新建编号的人，动手前先读完本章并填完表9-1。

### 表9-1 唯一标识声明表（新建表单**必须逐行填满**，12 项）

### 表9-2 前缀登记表（新增前缀必须在此登记；流水位数逐行标明）

| 前缀 | 业务对象 | 发号函数（所在文件） | 流水位数 | 状态 |
|---|---|---|---|---|
| `XSDD-` / `KCDD-` | 销售订单 / 库存订单 | `nextOrderNo(dateStr,type)`（`index.html`） | 5 位（`padStart(5)`） | 在用，**无副本**（批量库存订单走"基准号+偏移"，见下） |
| `JFJH-` | 交付计划 | `nextDeliveryPlanNo(dateStr)`（`index.html`） | 5 位（`padStart(5)`） | 在用，**无副本**（新增/回填/导入三处共用） |
| `PTH-` | 零部件入库流水 | `nextPartLogNo(dateStr)`（`index.html`） | 5 位（`padStart(5)`） | 在用，**无副本**（含 `used{}` while 去重兜底、读侧 trim 容错） |
| `PSCD-` | 排产单 | `ppNextId()`（`index.html`） | **3 位**（`padStart(3)`） | 在用，**但有 1 处内联副本** ⇒ 🔜 **D15** |
| `REP-` | 报工流水 | `prNextId()`（`js/prodplan-core.js`） | **3 位**（`padStart(3)`） | 在用；另有一处**一次性历史订正**内的拼接（`REP-20261006-` 硬编码，非活跃路径） |
| `YC-` | 质量异常记录 | `CORE.nextQaNo(list,now)`（`quality/qa-core.js`） | 5 位（`padStart(5)`） | 在用，**无副本**（新增 save / 服务端 409 suggest 共用） |

> **流水位数纪律**（新增，由 D15 复盘得出）：位数**允许 3 位或 5 位**，但必须在本表**逐行标明**，且同一编号的
> 「新增 / 回填 / 导入 / 拆单连号」**全部路径必须位数一致**。`padStart(3)` 与 `padStart(5)` 混用会产出
> "同前缀不同长度"的编号 ⇒ 正则 `\d{5}` 与 `slice(prefix.length)` 解析都可能错位（长度不同时 `slice` 取到的数字仍可解析，
> 但任何按固定长度切片的消费方会静默取错）。**位数一旦上线即不可改**（存量数据无法批量重号）。
>
> **登记纪律**：新编号前缀**必须先在此表加一行**再写代码。前缀是全局命名空间，撞前缀＝两类单据编号互相污染，
> 且**历史数据无法事后修复**（改了正则就认不出存量）。
>
> **"批量连号"的正确写法（已在本仓库存在，照抄即可）**：`saveBulkInvOrders`（`index.html`）的做法是
> —— 先调一次唯一发号函数拿**基准号**，再 `slice` 出前缀与起始序号，循环里 `seq++` 并用**已用集合（既有 + 本批新增）**
> 做 `while` 去重。这样既保证"一笔事务内连续不撞号"，又**没有第二份发号公式**。
> 这就是 D15 修复应当采用的范式（**不要**在事务里循环调用发号函数——第一次 push 前扫不到新单，会产出同号）。

### 表9-3 外键引用的三条硬约束（下游存储纪律）

### 9.3 一次性存量订正脚本的豁免口径（R4 的唯一例外）

**豁免**：一次性存量订正脚本（`_apply_NNN_*.js` 类，`.140` / `.142` / `.144` 都写过）允许**内联拼接编号**，
但必须**同时满足**以下三条，否则视为违反 R4：

- **(a) 硬编码到目标批次**：日期与序号直接写死（如 `'REP-20261006-' + padStart(3)`），**不扫描 max、不发新号**；
- **(b) 注释标明「非活跃路径」**：脚本内注明该拼接不参与日常发号，仅回填历史批次；
- **(c) 在版本时间线登记**：该批次号段在 `docs/kb/版本时间线.md` 留记录，便于日后核对"这批号是谁造的"。

| 判定 | 实例 | 为什么 |
|---|---|---|
| ✅ **属豁免** | `fixMisboundProdPlans20261012()` 里 `REP-` 的第二处拼接（日期硬编码、只造目标批次那一个号） | 满足 (a)(b)(c) 三条：它不回填出"未来的号" |
| ❌ **不属豁免（= 债务）** | `ppNextId()` 的**拆单内联副本** | **不满足 (a)**：它扫 `max+1` 并逐张发新号，是**活跃发号路径** ⇒ 登记为 **D15**，须按"基准号 + 偏移"范式收敛 |

> **判据一句话**：看这段代码**会不会产出将来的号**。会 ⇒ 它就是发号器，必须单源；只在造"历史某一天的号" ⇒ 可豁免。

### 表9-5 反例档案（7 条，每条都能回答"违反了会看到什么"）

| # | 反例 | 可观测症状 | 根因 | 现有守卫 |
|---|---|---|---|---|
| E1 | **索引漂移** | 某交付计划的"已排产 / 已交付"数字跳到不相干的计划上；超排角标只在**计划行级**可见，订单行级看不出来 | 只存索引不存外键；上游删一行，全库索引前移 | `ppDlIdxOf`、`prodplan.dlidx-relink §C-1` |
| E2 | **按行号取错行（串料）** | 报工后 A 产品的完成量记到 B 产品名下（C04.03.008 多出 1100 台）；或同产品多行明细下推后**两行数量变一样**（C02.02.026 的 480/240） | 按 `dlLine` 直取不校验 `productId`；用"产品级聚合 / 取首行"代替行级取值 | `ppDlRowOf`、`prodplan.dlidx-relink §A/§F`、`00-铁律速查 §5` |
| E3 | **同毫秒撞号** | 两条记录编号完全相同；导出再导入互相覆盖 | 用 `Date.now()` 或自增计数器发号；或只扫 max 不去重 | `nextDeliveryPlanNo` 的 `used{}` while、`nextQaNo`、服务端 409+suggest |
| E4 | **脏日期产出"形似合法"编号** | `JFJH-2026-8-5-00001`、`JFJH-202685-00001`（读作"2026 年 85 月"）——正则校验拦不住，因为**格式对了** | 日期串直拼，无格式守卫（`.134` 返工前的真实缺陷） | `nextDeliveryPlanNo` 的格式守卫 + 哨兵回落；`delivery.planno §A4` |
| E5 | **编号被手改** | 两人把编号改成同一个；下游外键全部指向错误目标；对账对不上 | 编号字段可编辑，或被前端放进请求体 | 只读 + 服务端 400「编号不可修改」（质量侧 §C4 钉住） |
| E6 | **删除后回收编号** | 删了 `00003` 再新增又得 `00003`，历史日志/导出无法区分两笔业务 | 维护独立序号计数器（第二真值源） | 禁止计数器，只用 max+1 + 去重兜底；且**不得**写回收表 |
| E7 | **导入重复追加** | 同一份 Excel 导两次，订单/明细翻倍 | 幂等键不是主键（用了"标题+日期"或"行号"当键） | `import.idempotent.test.js`（同一文件导两次不增生、三连导入仍只有一张单） |

> 四件缺一件，下游（下推 / 调用 / 报工回写 / 对账）就一定会出错，且出错时**表象与根因相距很远**（删 A 计划的后果出现在 B 产品上）。

## §10 【增强·可选】列宽 / 列序拖拽与持久化

**这章解决什么问题**：同一张表，每个人关心的列不同。不做也能用（见降级形态），但做了要守 6 个坑。

> **不做时的降级形态**：列序固定为 schema 顺序、列宽由浏览器 auto 布局决定。
> 代价：列多的表横向滚动很长、关键列可能被挤到屏幕外；**不得**为了让"看起来整齐"而写死列宽（会让长文本列永远截断）。

### 表10-1 交互与落盘时机

| 交互 | 触发 | 落盘内容 | 落盘时机 |
|---|---|---|---|
| 拖列宽 | `.th-rs` `mousedown` → 拖动 → `mouseup` | `widths[key] = round(th 实测宽)` | `mouseup` 后 |
| 拖列序 | `th` `mousedown` → 移动超 6px 死区 → `mouseup` 落在别的列上 | `order = reorderKeys(当前顺序, 被拖列, 落点)` | `mouseup` 后 |
| 重置 | 「重置列布局」按钮 | 清空自定义 ⇒ 回 schema 顺序 | 立刻 |
| 读取 | 页面初始化（`loadLayout` / `applyServerLayout`） | — | 渲染前一次 |

**拖动过程中的三个同步**：①拖动中实时把新列宽写进表体 `colgroup`（松开才写会跳变）；②拖动后 `syncHeadBody()` 再对齐一次；
③拖动后 `restoreTableScroll()` 复原横向滚动位置（否则视图跳回最左）。

### 表10-2 持久化两档（按系统选择，可升级）

| 档 | 存储介质 | 形状 | 适用判定 | 现有实现 |
|---|---|---|---|---|
| **L-a 本地** | `localStorage` | `{v:1, def:{模块:{order:[…],widths:{…}}}}` | 系统**没有** layout 接口／用户接受"换电脑重设" | 质量系统：键 `wb_cb_qa_tblLayout_v1` |
| **L-b 服务端账号分片** | 服务端数据文件（独立顶层键） | `{v:2, def:{模块:{…}}, u:{用户名:{模块:{…}}}}` | 有鉴权体系、且要求"换设备/换浏览器仍一致" | 生产系统：`tblLayout`，`POST /api/layout`（**刻意不带 `expectedRev`** ⇒ 分片天然无冲突、无 409） |

**升级路径（L-a → L-b，零数据迁移）**：L-a 的 `def` 层与 L-b 的 `def` 层**同构**。升级时只需：
①形状版本号 `v:1 → v:2`；②加 `u` 对象；③读取侧加一句「`u[当前用户]` 优先，缺失/非法则回落 `def`」。
**不要**重新设计一套形状——那会让两端各写一份归一逻辑。

**两档共同的读取纪律**：
- `def` = 所有人的初始布局；`u[用户名]` = 该账号自己的布局。
- 读入时必须**深拷贝**（绝不能与 `def` 本体共享引用，否则某人拖一次列会污染"所有人的初始值"）。
- **非法分片一律回落 `def`，不得回落空 `{}`** —— `{}` 是"该账号自己的（空）布局"＝看到系统默认列序，
  与"无分片 ⇒ 回落初始布局"的用户可见结果**不同**。
- 归一化（`normalizeLayout`）**只在读取路径**做（剔除未知列 key / 非数字宽 / 重复项）；
  **保存时必须原样落盘用户拖出的顺序**，不得在保存时"顺手纠正"——那等于静默改写用户意图。

### 表10-3 六个坑（全部有真实来源）

| # | 坑 | 违反后表现为 | 正确做法 |
|---|---|---|---|
| 1 | **按物理下标移动单元格**（而非按列身份） | 库存表/合并表错列；带 `colspan` 的汇总行被拆散 | 按列身份属性匹配重排；**含 `colspan` 的行整行跳过** |
| 2 | **拖完紧跟的 `click` 改排序** | "我就拖了一下列宽，怎么顺序也变了" | `window.__colDragTS` + `toggleSort`/`sortBy` 首行 350ms 抑制 |
| 3 | **拖完视图跳回最左** | 拖右边的列，表格瞬间回到第一列 | `restoreTableScroll()`：双 `requestAnimationFrame` + 150ms 兜底（列宽变了 `scrollWidth` 需 reflow 才稳定） |
| 4 | **不设最小列宽** | 列拖到很窄后标题消失、`⇅`/漏斗被吃掉 | `minThWidth`（见 §5.2），`Math.max(minW, 目标宽)` |
| 5 | **新增列落在最末** | 新加的列跑到表格最后一个（用户找不到） | `applyTableLayout` 的插入规则 =「已存 `order` 中仍存在的列保持原相对顺序」+「新列**追加到末尾**」 ⇒ 给已存过布局的表加列时，须**清掉该表的 `order`**（可保留 `widths`）才能让新列回到设计位置 |
| 6 | **读/写都做归一化** | 用户拖出的顺序被静默改写；或某次归一 bug 把所有人的布局洗掉 | 归一**只在读**；写原样落盘 |

## §11 【增强·可选】sticky 双表 + 底部固定横滚条

**这章解决什么问题**：1000 行 × 20 列的表格，用户滚到第 300 行就不知道每列是什么了。

> **不做时的降级形态**：只用一个普通 `<table>`（`thead`+`tbody`），表头随页面滚走。
> 代价：长表必须靠记忆对列；横滚必须滚到表格底部才能拖动原生滚动条（长表几乎不可用）。

### 表11-1 双表结构对照

| 项 | 表头表（`table.head-tbl`） | 表体表（`table.body-tbl`） |
|---|---|---|
| 所在容器 | `.sticky-head` > `.head-scroll` | `.table-wrap` |
| 内容 | `colgroup` + `thead`（**无 tbody**） | `colgroup` + `tbody`（+ 合计行） |
| 吸附 | 由外层 div 做 `position:sticky` | 不吸附 |
| 承载 rowspan 整单合并 | ❌ **禁止** | ✅ 唯一承载者 |
| 列宽来源 | **自身 `th` 的实测宽度（唯一真源）** | 由 `syncHeadBody()` 从表头 `th` 宽写入 `colgroup` |
| 布局 | `table-layout:fixed` | `table-layout:fixed`（两表都要） |

**四个必须成对存在的函数**：`syncHeadBody()`（列表宽）、`fixStickyHeadTop()`（算吸附 top）、
`restoreTableScroll()`（滚动复位）、滚动跟随委托（表体横滚 → `.head-scroll` 跟随）。
**渲染后调用顺序不可颠倒**：`applyTableLayout()` → `syncHeadBody()` → `fixStickyHeadTop()` → `syncBottomScrollbar()`。
（先设宽才能同步宽；吸附位置要读操作栏实际高度；底部条要读最终 `scrollWidth`。）

### 表11-2 吸附 top 计算式（`fixStickyHeadTop`）

```
top = 基准(桌面 58 / 移动端 48)
    + 操作栏(.bulk-bar) 的 marginTop + offsetHeight + marginBottom
    + 【若有筛选条】(.tbl-fbar) 的 marginTop + offsetHeight + marginBottom
表头容器 top = top
筛选条 top = 操作栏结束处，zIndex 30（叠在表头之下、操作栏之上）
```

- 操作栏在卡片内时必须 `margin-bottom:0`（`.card .bulk-bar`），否则未滚动时表头与操作栏之间露一条缝（生产 `.14` 踩过）。
- 窗口 resize 时要重算（操作栏会换行、高度变化）。

### 表11-3 为什么不能用 `thead{position:sticky}`

| 原因 | 说明 |
|---|---|
| Chrome 渲染 bug | `table-layout:fixed` + `rowspan` 整单合并下，`thead` 的 sticky 会错位/闪烁（生产 `.6` 实验后回滚） |
| 列宽无法与表体解耦 | 同一个 `table` 里表头表体同宽，需要"表头缩到很窄但表体内容不撑宽"时无解 |
| 滚动条位置 | 表体需要独立横滚容器，表头必须跟随——两表 + `scrollLeft` 同步是唯一稳的路子 |

**底部固定横滚条**：表体自身横条必须隐藏（`scrollbar-width:none` + `::-webkit-scrollbar{display:none}`），
横向滚动统一交给页面底部 `#bottomScrollbar`（`position:fixed;bottom:0`），两侧双向同步。
**漏隐藏原生条的表现**：表格下方出现**两条**横滚条，用户不知道该拖哪条。

## §12 【增强·可选】合计行

**这章解决什么问题**：用户要"这 1000 条一共多少"。合计行写错的两个经典形态——**随翻页跳变**、**拖列后错位**。

> **不做时的降级形态**：不显示合计，或提供一个「导出后用 Excel 求和」的提示。
> 代价：每次核对数量都要导出；且长表人工求和必然出错。

### 表12-1 合计口径

| 项 | 规则 | 为什么 |
|---|---|---|
| **范围** | **筛选 + 排序后的全量、分页前**（生产传 `allShown`/`shown`；质量传 `orderedRecords()`） | 传当前页 ⇒ 翻页时合计数字跟着变，用户无法用它核对总量 |
| **禁传** | 分页窗口（`pg.rows`） | 质量侧注释明确写了这一行"最容易写错" |
| 参与列 | `type==='number'` 且**不在 `SUM_SKIP_KEYS`** | 比率/进度列求和没有业务含义 |
| `SUM_SKIP_KEYS` | 生产 `{_pct, _balPct}`；质量 `{}`（暂无比率列，**机制保留**） | 新增比率列时**登记到这个常量**，不要在 `sumColKeys()` 里另写排除条件 |
| 标签列 | **当前布局 `order` 里第一个非数字列**；`order` 为空则回落 schema 首个非数字列 | 避免标签挂在"被拖到表格角落的 schema 首列"上（生产 `.113`） |
| 插入位置 | 表体表 `tbody` 的**最后一行**（`</tbody>` 之前） | **不用 `<tfoot>`**：fixed + 双表结构下 `tfoot` 会被排除在重排之外 |
| 空数据 | 返回空串（不渲染空合计行） | — |
| 勾选 | 首列是**空 `td`**，不含 checkbox（合计行不参与勾选） | 否则全选会把合计行算进去 |

### 表12-2 逐列同构要求（`.112` 事故的防线）

| 要求 | 说明 |
|---|---|
| 每个 `td` **都必须带列身份属性**（生产 `data-key` / 质量 `data-col`） | 有值的、空的、文本的、比率的——**一个都不能少** |
| 文本/比率列也要输出**空 `td`** | 只输出数字列 ⇒ 列数比数据行少，整行与表头错列 |
| 数值右对齐 + `font-variant-numeric:tabular-nums` | 与数据行数字列同款，竖排可比 |
| 标签单元格写「合计」 | 不要写「总计/小计/合计值」等变体（同一系统内必须统一） |

> **违反后表现为**（`.112` 原始事故）：合计行只有几个数字 `td`、无列身份，用户拖一次列后
> **所有合计数字挤到行尾、与表头完全对不上**，而且**不会报错**。

## §13 【增强·可选】cell-tip 单元格悬浮

**这章解决什么问题**：列宽有限、长文本必须截断，但用户要能看到全文。

> **不做时的降级形态**：给单元格加原生 `title=全文`。
> 代价：原生 tooltip 延迟 1~2 秒、样式不可控、移动端不出现；且**与自定义 tip 并存会双弹**（生产 `.89` 踩过）。

### 表13-1 判定与例外

| 场景 | 处理 | 原因 |
|---|---|---|
| 判断"是否被省略" | **临时 `span` 探针测完整文本宽**（脱离文档流 + `nowrap`），与单元格可用宽比较 | ellipsis 下 `scrollWidth` / `Range` 都不可靠 |
| 带 `[data-tip]` 的元素 | **优先**显示 `data-tip` 内容 | 语义提示（如三角警示的数值解释）需要自定义文案 |
| `select` 元素 | 取**当前选中项**文本；`document.activeElement === select` 时**不显示** | `innerText` 会把全部 `option` 拼起来 ⇒ 误判截断 + 巨大浮框 |
| 含控件（`select/input/textarea/button`）的单元格 | **不显示** | 同上，浮框会遮挡控件 |
| 普通 `td` / `.th-label` | 文本被省略时显示全文 | 表头列名也可能很长 |
| 定位 | `position:fixed` 跟手；右侧/底部放不下则**翻到左/上**（留 8px 边距） | 表格靠右边缘时浮框会出视口 |
| 隐藏 | `mouseout` 且指针离开该单元格时 | — |
| 与 ellipsis 的关系 | 单元格必须真的被 `ellipsis` 截断（如 `.col-clip`），否则永远测不出省略 ⇒ tip 永不出现 | 长文本列必须同时给截断样式 |

> **全站只许一个 `.cell-tip` 容器**；`bindCellTip()` 只在初始化时注册一次。
> **违反后表现为**：鼠标划过单元格同时冒出两个提示框；或长表滚到右侧后浮框跑到屏幕外看不见。

## §14 【增强·可选】rowspan 整单合并

**这章解决什么问题**：订单类表格一张单有 N 行明细，单据级字段（客户、状态、单据日期）只在第一行显示，视觉上一张单是"一块"。

> **不做时的降级形态**：每行重复显示单据级字段（等价于笛卡尔展开）。
> 代价：视觉噪音大，但**功能无损**——排序/筛选/合计/勾选全部照常。
> **结论**：只有"单据级字段多、明细行少"的表值得做；**质量台账这类"一记录一行"的单行模型禁止做**（纯增复杂度）。

### 表14-1 适用性判定

| 行模型 | 判定 | 系统实例 | rowspan |
|---|---|---|---|
| **组模型**（一行属某单据，单据有多行明细） | 需要 `groupKey` 让**整单不拆页** | 订单（`order_frame` / `order_inv`）、交付计划、排产计划 | 单据级列合并；**只在表体表里合并**（表头表禁止） |
| **单行模型**（一记录一行） | 不需要 `groupKey` | 产品、零部件、调拨、日志、零部件流水、**质量台账** | ❌ 不做 |

### 表14-2 与其它能力的四处联动（做 rowspan 就必须同时处理）

| 联动点 | 要求 |
|---|---|
| 列身份 / 重排 | 每行的**实际存在的列**才带列身份属性；重排只移动"该行有的列"（不能假设每行列数相同） |
| 合计行 | 合计仍按**行级明细**求和（与合并无关）；合计行本身**不合并**、逐列同构 |
| 勾选 | 选中态必须**传播到整单所有行**（`updateSelUI`），否则删一半留一半 |
| 分页 | 必须传 `groupKey`（整单不拆），页码信息区显示 `(M 张)` 而不只是条数 |
