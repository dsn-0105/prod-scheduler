## 1. 系统概览

- 用途：某智能低压断路器公司自研生产排产系统，面向约 10 人团队多员工在线使用。
- 形态：单文件 HTML（`index.html`，Vanilla JS 零依赖）+ 零依赖 Node 后端（`server/server.js`）。
- 模式：服务器模式（`API_BASE='/api'`）多员工共享；本地单机把 API_BASE 改 `''` 回退 localStorage。
- 线上地址：http://<PROD_SERVER_IP> （腾讯云 Lighthouse，Ubuntu 24.04，2C2G4M，上海）。
- 仓库：`dsn-0105/prod-scheduler`（Public），GitHub Pages：https://dsn-0105.github.io/prod-scheduler/

## 2. 架构与代码地图（index.html）

### 数据层
- `DB.get/set` 异步抽象（index.html:332）：服务器模式 fetch `/api/*`，本地模式 localStorage（KEY=`wb_cb_prod_`）。
- `pullAll()`（327）：拉全量 `serverData` + `serverRevs`；`pollRevs()`（355）：每 5 秒轮询 `/api/revs`，版本变化 → pullAll → renderContent。**注意 pullAll 只更新 serverData，不重赋值全局数组**（全局 orders 等引用 initApp 时赋值）。
- `DB.set` 已加固：非 2xx 弹「保存失败」，不静默。

### 表格引擎
- `TBL_SCHEMAS`/`TBL_ROWS` 按 formKey 隔离；`applyTable`=sortRows+filterRows。
- `tState(m)`（780）：排序/筛选状态，**纯内存态**，刷新即重置。
- `thCol`（~846）渲染表头（.th-label + 排序/筛选图标）；列可拖拽排序/调宽（tblLayout 持久化）。
- `updateSelUI`（4513）：选中行局部刷新（checkbox + `row-sel` 透明蓝高亮 + rowspan 整单传播），不整页重渲染；`renderContent` 末尾对 6 表单同步选中态。
- 单元格/表头省略悬停：`.cell-tip` 事件委托 + 临时 span 探针测宽（`truncated`，offsetWidth）。

### 业务模块
- 产品主数据 `renderProducts`、订单管理 `renderOrders`（orderSection 分「销售订单」/「库存订单」两区块，formKey `order_frame`/`order_inv`）、排产计划 `renderProdPlan`（formKey `prodPlan`，2026-08-24.6 起替代旧「日排产」页签，月/周/日三视图 + 报工）、交付计划 `renderDelivery`、调拨台账 `renderTransfers`、操作日志、员工管理（admin 专属）。
- 旧「日排产/生产日报」页签已下线（NAV 移除），`renderDailyPlan`/`renderDailyReport` 函数保留不调用，dailyPlans/dailyPkgs 数据保留备份。
- 弹窗：`showModal`（z-index 200）；产品选择器 `productPickerModal`（二级浮层 z-index 250，mode single/multi，含列筛选）；超量确认浮层 `showConfirmOverlay`（z-index 300）。

## 3. 数据模型与关键字段

### 产品（products）
`id`（编码）、`name`（名称）、`spec`（规格）、`model`（型号）、`unit`（单位）、`stock`（**库存/已交付数量**，关键字段）、`dailyCap`（日产能，单一字段）、`stockMin`/`stockMax`、`status`。
> 注意：产品主数据**无「描述」字段**（金蝶导入的商品描述仅展示不落库）。

### 订单（orders）
- 头：`id`（单据编号）、`orderType`（**销售订单/库存订单**，select，options 定义于 fields 配置，勿残留旧值）、`customer`、`contractNo`（销售订单必填）、`startDate`、`deadline`、`status`（待排产/执行中/已完成/已取消）。
- 明细 items[]：`productId`、`productName`、`spec`、`model`、`unit`、`orderQty`、`deliveredQty`、`stockMin`、`stockMax`、`lineNotes`。
- 扩展字段：金蝶导入订单带 `src='kingdee'` + `srcFile`（**编辑时必须保留**，saveOrder 已拷贝）。
- 前缀：销售 XSDD-、库存 KCDD-（`migrateInventoryOrderIds` 迁移过）。

### 调拨台账（transfers）
调用/退回/冲销记录，只读流水表；系统键，登录用户可写。
- **服务器表键注册（坑位）**：`transfers` 必须同时在 `server/server.js` 的 `DEFAULT_DATA`（决定 `/api/save` 的 `b.key in data` 校验与 data.json 落盘）与 `SYSTEM_KEYS`（决定写权限）中登记；曾漏 DEFAULT_DATA 导致一切 `save('transfers')` 返回 400「未知数据表」而订单侧已成功（隐蔽丢台账，2026-08-24.5 修复）。新增任何数据表均须两处同步登记。

### 交付计划（deliveries）
- 头：`orderId`、`customer`、`finalDate`（最终交付期）、`firstDate`（首次交付日）、`planQty`（**本批计划交付数量 = Σ 明细行 planQty，自动汇总**）、`notes`、`orderTotal/delivered/undelivered`（由明细行汇总）。
- 明细 items[]：`productId`、`productName`、`spec`、`model`、`orderQty`、`deliveredQty`、`planQty`（**行级本批计划交付数量，可编辑，留空=本批不交付**）、`lineNotes`。
- 弹窗交互（build 2026-08-23.39 起）：表头无单值"本批计划交付数量"输入框，改在明细表逐行填写；校验：至少一行 >0 才能保存；行级超量（行 planQty > 该行未交付）弹确认浮层列出明细。
- 老数据兼容：历史 items[] 无 planQty 字段 → 编辑时显示空需补填，表头 planQty 在保存时被行级汇总覆盖。
- 产品信息回填（build 2026-08-23.40 起）：金蝶导入落库 items 时回填 productName/spec/model（以产品主数据为准）；deliveryOrderChange 带出明细时对空字段按 productId 查主数据回填；历史订单已由服务器脚本批量回填（备份 data-pre-fix-prodname-*）。

### 排产计划（productionPlans，2026-08-24.6 新增）
- 头：`id`（单号 PSCD-日期-序号，ppNextId 自动生成）、`deliveryIdx`（**来源交付计划索引，快照语义**——下推后与交付计划脱钩，改交付计划不影响已下推排产单）、`orderId`/`customer`/`finalDate`（快照）、`planDate`（计划生产日期，下推=finalDate 可改）、`status`（待排产/生产中/已完成/已取消）、`notes`。
- 明细 items[]：`productId`/`productName`/`spec`/`model`/`unit`、`planQty`（**= 交付计划行 planQty，1:1 无排产系数，2026-08-24 用户确认**）、`doneQty`（**= 成品入库 finInbound 累计，唯一完成口径，为二期回写预留**）、`lineNotes`、`steps`（6 工序：assembly/innerPack/testAging 为 {plan,done}，semiInbound 单值，pkg 为 {plan,done}，finInbound 单值）。
- **月/周是视图不是表**（方案 A）：按 planDate 聚合，周复用 `getWeekStart`（周一起点），月按自然月；`planView`/`planViewDate` 纯前端状态。
- 服务器表键：`productionPlans` 已在 server.js `DEFAULT_DATA`（[]）与 `BIZ_KEYS` 登记（防 transfers 坑）；前端 `formToKey` 加 `prodPlan:'dailyPlans'` **复用旧日排产权限位**（无需改 users.json），员工管理权限文案「排产计划」。

### 字段配置（fields）
- `fields.order` 持久化于服务器 data.json；**改字段/改名必须同步迁移持久化配置**（见坑位 1）。
- 系统字段 orderType/contractNo locked，`migrateOrderTypeField`/`migrateOrderContractNo` 兜底。

## 4. 业务规则

- 库存打通：`syncStockFromInvOrders()` — **全量对齐口径（2026-08-23 用户确认）**：所有产品 stock=Σ(库存订单已交付)，无库存订单产品一律归零；期初库存经 `backfillInvDeliveredFromStock` 反填进订单后走本口径。删除/恢复回滚库存订单后库存自动对齐，杜绝孤儿库存残留。保存/删除库存订单时自动同步。
- 排产计划：交付计划页「下推排产计划」`genProdPlan`（选中 1 条交付计划 → 1 张排产单，planQty=0 行跳过，可重复下推分批生产）；报工 `reportProdPlan`/`saveReport`（选中 1 条排产单 → 弹窗按工序填**本次完成数（增量）**，必报工序=装配/包装/成品入库（可填 0），其余可留空；超量=工序累计>计划量 → `showConfirmOverlay` 浮层确认；首次报工自动置「生产中」，全部行 doneQty≥planQty 提示标「已完成」；logOp 留痕）。**报工不自动回写订单/库存（二期口径待定，doneQty=finInbound 为衔接点）**。
- 调拨：销售订单「调用库存」→ 库存订单已交付↓、销售订单已交付↑（`applyStockMove`）；「退回库存」反向；`reverseTransfer` 冲销。
- 金蝶导入：`triggerImportKingdee` → `importKingdeeXLSX`（合并单元格展开、表头关键字映射 `kdMapHeader`）→ 只读预检 `kdPrecheckAndShow`（问题：合同号/客户空、日期缺失、订单号冲突、未知产品编码、行跳过；超阈值 blocked）→ `kdShowReport`（未知产品编码行：紧凑两行信息 + [选已有产品]弹产品选择器/[新建]，决策位 `kd_unk_dec_{idx}` 局部刷新）→ `kdDoImport` 幂等写入（覆盖/跳过/改名）。
- 版本号：index.html 中 `build X.Y` 占位；GitHub push 后 workflow sed 注入 `日期.全局run_number`。
