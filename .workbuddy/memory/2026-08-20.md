## 产品复选弹窗修复 + 列头筛选样式（commit c7008c5，未 push）

## 批量选择弹窗「添加/完成」分离（commit b761cbe，未 push）
- 反馈：新建订单时，批量选择产品处点击「确认」弹窗也会直接消失。
- 根因：之前设计是「确认 = 一次性添加所有勾选 + 关闭弹窗」，与「批量选择」多次添加的语义不符——用户点确认后希望继续选，弹窗却关了，体验差。
- 改动：多选模式底部按钮改为「取消 / 添加 / 完成」三按钮：
  - **添加**：收集勾选产品 → 调用 onConfirm（追加为新明细行）→ **不关闭弹窗** → 自动清空已添加的勾选，方便用户继续选下一批。

  - **取消**：关闭弹窗，不调用 onConfirm（已添加的保留）。
  - 单选模式仍保留「确认」一键选中+关闭（兜底，未来如需单选可用）。

## 修复：添加产品后仍残留空行（commit 4847bb8，未 push）
- 反馈：当产品行完全为空时，新增产品还是存在一条空行。
- 根因：`removeEmptyOrderItems()` 内置的「删空后无行则补空行」兜底逻辑在**追加新行之前**执行——空行被删后立刻被兜底补回，追加完产品行后明细表就多出一条空行。
- 改动：`removeEmptyOrderItems()` 只负责删空行，不再补行；新增 `ensureOrderItemRow()`（明细表无任何行时补一行空行），在 `openProductPicker`/`batchPickProducts` 的 onConfirm **追加完成之后**调用。结果：勾选了产品 → 只显示产品行（无空行）；未勾选 → 保留一行空行供手动录入。
- 版本号 bump 至 `build 2026-08-19.14`；语法 `node --check` 通过；已 commit `4847bb8`（未 push）。

## 修复：仅第一次添加产品行出现空行（commit 1a676b6，未 push）
- 反馈：新增订单后第一次添加产品行仍有空行；但删光产品行后再添加就不会——只有第一次会。
- 根因：新增订单初始空行来自 `orderItems(o)` 兜底（`o.items` 为空数组时返回 `[{productId:undefined, orderQty:num(undefined)=0,...}]`），渲染出 orderQty 输入值为 **`0`**；而 `removeEmptyOrderItems` 需「productId 空 **且** orderQty 空」才删，`'0'` 非空 → 第一次删不掉。删光后由 `orderItemRow({})` 补的空行 orderQty 是空字符串 → 能删。
- 改动：
  1. `orderItems(o)`：`items` 为空数组时返回 `[]`（新增订单不再生成默认空行），仅平铺旧数据（无 items 属性）保留兜底；全部调用点（汇总、看板、导出、日志）空数组均安全。
  2. `removeEmptyOrderItems` 判定放宽为**产品编码为空即删**（兼容数量为 0 的历史空行；无 productId 的行本来也无法保存）。
- 版本号 bump 至 `build 2026-08-19.15`；语法 `node --check` 通过；已 commit `1a676b6`（未 push）。

## 修复：表头拖拽调序后数据不跟随（commit ee6e784，未 push）
- 反馈：表单的字段名称左右移动后，下方数据不会跟随移动。
- 根因：`applyTableLayout` 重排依赖「物理索引 + 行列数与表头一致」——订单表格（框架/库存订单）有 **rowspan 合并单元格**（订单级 5 列合并），非首行 `cells.length`（12+1）≠ 表头（17+1）→ 被 `if(row.cells.length!==headCells.length)return` 跳过 → 表头移动了、明细数据不跟随。
- 改动：
  1. 订单表格 `renderOrderTable` 行渲染：所有数据 td 加 `data-key`（deadline/startDate/id/customer/status + productId...lineNotes，与表头 key 一一对应）。
  2. `applyTableLayout` 重排改为两级策略：行内带 data-key 的 cell ≥2 → **按 data-key 匹配重排**（appendChild 移动，每行只移动该行实际存在的列，rowspan 行自动正确）；无 data-key 的行（产品/排产/报表/日志等）且列数与表头一致 → 退化为原物理索引重排，行为不变。
- 版本号 bump 至 `build 2026-08-19.18`；语法 `node --check` 通过；已 commit `ee6e784`（未 push）。
