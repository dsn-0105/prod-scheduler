## 产品复选弹窗修复 + 列头筛选样式（commit c7008c5，未 push）
- 反馈：
  1. 刚加的复选弹窗有 bug，选择产品时弹窗会直接被关闭。
  2. 复选框选择产品时，筛选功能放在每个字段处，样式参考其他表单（如产品主数据）。
- Bug 根因：`<tr>` 上挂了 `onclick="ppRowClick(this)"`，导致点击 checkbox 时浏览器先翻转 checked，事件冒泡到 tr 又翻转一次（用户感觉「勾不上」）；单选模式点行直接 `closeModal()`，体验上像「关闭 bug」。
- 改动：
  - 去掉 `<tr>` 的 onclick，行不响应点击；用户通过首列的 radio/checkbox 切换。
  - 底部始终显示「确认」「取消」按钮，按确认才关闭（不再因点行直接关闭）。
  - 重写列头：每列渲染 `列名 + 漏斗筛选图标`（`FILT_SVG`，与产品主数据表格的 `thCol` 同款），点击漏斗打开 `filt-pop` 筛选弹窗。
  - 筛选弹窗按列类型自适应：文本列（≤15 个唯一值或 select 列）渲染复选框；数值列渲染「≥/≤/=/≠」模式 + 数值输入；其余文本列渲染「包含/=/≠」模式 + 关键字输入。每列可独立筛选，多列条件同时生效。
  - 新增 `ppOpenFilter` / `ppApplyFilt` / `ppClearFilt` / `ppFiltCheckAll` / `ppRenderRows` / `ppUpdateHeader` 系列函数；`PP_SCHEMA` 抽离为列定义，复用 `filt-pop` 样式。
- 版本号 bump 至 `build 2026-08-19.9`；语法 `node --check` 通过；已 commit `c7008c5`（未 push）。

## 批量选择弹窗「添加/完成」分离（commit b761cbe，未 push）
- 反馈：新建订单时，批量选择产品处点击「确认」弹窗也会直接消失。
- 根因：之前设计是「确认 = 一次性添加所有勾选 + 关闭弹窗」，与「批量选择」多次添加的语义不符——用户点确认后希望继续选，弹窗却关了，体验差。
- 改动：多选模式底部按钮改为「取消 / 添加 / 完成」三按钮：
  - **添加**：收集勾选产品 → 调用 onConfirm（追加为新明细行）→ **不关闭弹窗** → 自动清空已添加的勾选，方便用户继续选下一批。
  - **完成**：关闭弹窗（已添加的已生效，无需再回调）。
  - **取消**：关闭弹窗，不调用 onConfirm（已添加的保留）。
  - 单选模式仍保留「确认」一键选中+关闭（兜底，未来如需单选可用）。
- 版本号 bump 至 `build 2026-08-19.11`；语法 `node --check` 通过；已 commit `b761cbe`（未 push）。

## 产品选择改「二级浮层」+ 双按钮确定/取消（commit 8446b0e，未 push）
- 反馈：批量选择产品只需两个按钮：「取消」（回到新增订单，不改动）和「确定」（回到新增订单，选中条目追加到订单明细下方，原有数据不覆盖）。
- 真正根因：之前 `productPickerModal` 用 `showModal` **替换**了 modal 的 innerHTML，导致底层「新增订单」的 DOM（含 `#orderItemsTbl`）从页面消失，onConfirm 里 `document.querySelector('#orderItemsTbl tbody').insertAdjacentHTML(...)` 拿到 null 报错——弹窗正常关但明细行加不上。
- 改动：
  - `productPickerModal` 改为**创建二级浮层**（`div#ppOverlay.modal-bg`，z-index:250，半透明遮罩，内部 `.modal` 结构复用 modal-head/body/foot 样式），不再替换底层弹窗 DOM → 「新增订单」表头输入值、明细天然保留。
  - 底部仅两个按钮：**取消**（移除浮层，不回调，回到底层）与**确定**（移除浮层 → 回调 onConfirm → 把选中条目追加到 `#orderItemsTbl` 下方，已存在的跳过，不覆盖原有数据）。
  - 删除多选模式下的 `ppAppend`/`ppDone` 三按钮逻辑；`ppCancel`/`ppConfirm` 改为移除浮层并 `closeFiltPop()`。
- 版本号 bump 至 `build 2026-08-19.12`；语法 `node --check` 通过；已 commit `8446b0e`（未 push）。

## 修复：添加产品后仍残留空行（commit 4847bb8，未 push）
- 反馈：当产品行完全为空时，新增产品还是存在一条空行。
- 根因：`removeEmptyOrderItems()` 内置的「删空后无行则补空行」兜底逻辑在**追加新行之前**执行——空行被删后立刻被兜底补回，追加完产品行后明细表就多出一条空行。
- 改动：`removeEmptyOrderItems()` 只负责删空行，不再补行；新增 `ensureOrderItemRow()`（明细表无任何行时补一行空行），在 `openProductPicker`/`batchPickProducts` 的 onConfirm **追加完成之后**调用。结果：勾选了产品 → 只显示产品行（无空行）；未勾选 → 保留一行空行供手动录入。
- 版本号 bump 至 `build 2026-08-19.14`；语法 `node --check` 通过；已 commit `4847bb8`（未 push）。
