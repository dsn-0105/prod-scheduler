## 修复编辑库存订单保存后转移到框架订单（commit b22e9fe，已部署）
- 现象：编辑已有库存订单保存后，该订单跑到框架订单区块。
- 根因：`orderType` 字段 `locked:false`，字段设置中可被删除；一旦 fields.order 缺失该字段，编辑弹窗不渲染「订单类型」输入 → saveOrder 收集不到 orderType → `orderTypeOf` 默认归为「框架订单」。（新增有 pendingOrderType 兜底所以正常，编辑无兜底。）
- 修复三层：①saveOrder 编辑时若收集不到 orderType 则保留原订单类型（无则默认框架）；②defaultFields.order 的 orderType 改 locked:true（防误删）；③新增迁移函数 `migrateOrderTypeField()`（字段配置缺失则补回并锁定，未锁定则强制锁定），在 bootstrap 迁移链末尾调用。
- build 2026-08-21.14，已 scp 部署。

## 库存订单已交付数量同步产品库存（commit 5502f3d，已部署）
- 业务口径（用户澄清）：库存订单=生产入库到成品库，交付多少就是多少库存；「已交付数量」=库存量。未来会加「框架订单调用库存」功能（库存订单已交付中扣减），现在不做。
- 实现：`syncStockFromInvOrders()`——产品主数据库存 = 全部库存订单明细 deliveredQty 之和（按产品汇总，多订单/多行正确）；只更新出现在库存订单中的产品（不误清零期初/手动库存）；保存库存订单（saveOrder）与删除库存订单（delOrder）后触发；bootstrap 迁移链首次加载时执行一次对齐存量。
- 说明：框架订单已交付不参与库存；看板库存快照/缺货预警自动反映。
- build 2026-08-21.19，已 scp 部署。
