## 真正根因：orderType 字段配置残留旧选项「框架订单」（commit 8eb5741，build 2026-08-23.38）
- **推翻上一条"恢复备份"推断**：用户澄清今天未恢复备份，12 张新增订单是**金蝶导入**；「框架订单」就是用户之前改名的「销售订单」。
- 铁证（服务器日志 2026/8/23）：`12:06:45 XSDD-20260520-00001：销售订单→框架订单`、`12:09:11 XSDD-20260406-00006：销售订单→框架订单`、`13:16:45 XSDD-20260505-00011：销售订单→框架订单` —— 用户每次编辑销售订单，orderType 都被改成「框架订单」→ 订单不在销售/库存区块 → 整单消失；刷新 initApp 迁移又改回 → "又出现"。
- 根因：服务器 `fields.order` 里 orderType 持久化配置仍是 `options:['框架订单','库存订单'], default:'框架订单'`（改名时只改了代码常量 ORDER_TYPES，没迁移已持久化的 fields 配置）。编辑弹窗 select 用**服务器字段配置**渲染，本地订单为'销售订单'但 options 无此选项 → 浏览器默认选中第一项'框架订单' → 保存即误改。新增订单不受影响（pendingOrderType 强制覆盖）。
- 修复：
  1. 数据：服务器 fields.order orderType → `options:['销售订单','库存订单'], default:'销售订单'`；残留 1 张框架订单 → 销售订单（已备份 data-pre-optfix-*，重启 prod-server）。
  2. 代码：`migrateOrderTypeField()`（index.html:1779）增强——若 options 缺'销售订单'或含'框架订单'，对齐 ORDER_TYPES 并重写 default，幂等自愈（任何加载路径都会修正并写回）。
- 校验：node --check SYNTAX_OK；线上 grep 修正选项文案=1、build 2026-08-23.38=1；服务器残留框架订单=无。
- 部署：本地 commit 8eb5741，已上线；GitHub 推送由用户手动执行。
- 教训：**改名类功能必须同步迁移持久化字段配置（fields 表）**，只改常量不够；排查"编辑后消失"先看 logFieldDiffs 日志的字段 diff。

## 悬停提示单字省略不生效 + 滚动修复补齐上线（commit 835233a，build 2026-08-22.31）
- 悬停 bug：原 `truncated(el)` 用 `el.scrollWidth>el.clientWidth+1`。只省略**一个中文字**时，浏览器对带 ellipsis 的 `td` 返回 `scrollWidth≈可见宽度(含省略号)`，而非完整文本宽度 → 判定 false，提示不弹。
