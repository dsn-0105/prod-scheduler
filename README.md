# 生产排单与报表系统

面向智能低压电器（断路器）制造企业的**单文件网页版**销售订单 / 生产排产 / 交付管理系统。零依赖、纯前端实现，数据默认存于浏览器本地，可无缝升级到服务器后台。

> 当前版本：`build 2026-10-21.155`

## 功能模块

左侧菜单共 **10 项**（按业务顺序；支持长按拖动调整，顺序随用户持久化）：

| 模块 | 说明 |
|------|------|
| 产品主数据 | 产品编码 / 名称 / 型号 / 规格 / 单位 / 日产能 / 库存上下限 / 关联工序模板；**库存 = 该产品所有库存订单已交付之和，系统自动汇总，不可手工填** |
| 订单管理 | 销售订单与库存订单双区块（`order_frame` / `order_inv`）：表头 + 明细行、交付 / 退货、调用 / 退回库存、金蝶 xlsx 导入（预检报告 → 未知商品编码决策 → 幂等写入） |
| 库存管理 | 库存订单独立页签，按库存直发 / 备货；**无「数量」字段，数量 = 最大库存量**；「生成交付计划」唯一入口（.95 起）；「库存调整」盘盈 / 盘亏 |
| 排产计划 | 生产排产主链：库存订单 → 交付计划下推 → 投产 / 工序报工 → 入库自动回写订单；月 / 周 / 日三视图 + 报工明细；内置一键自检 |
| 交付计划 | 按交付频率自动倒排批次排期，支持实际交付填报与差异对比；下推排产计划；「已计划未交付 / 结余」口径（与已交付同源、不钳制） |
| 工序模板 | 工序步骤定义；产品必须关联工序模板（独立权限） |
| 操作日志 | 字段级变更追踪（旧值 → 新值），覆盖全部增删改导入导出操作 |
| 使用说明 | 内置使用手册（随版本更新），覆盖各模块口径与常见操作 |
| 调拨台账 | 调用 / 退回 / 改装 / 移库 / 盘盈 / 盘亏及各自冲销的流水台账（8 态）；支持备注与按订单「调拨查询」 |
| 员工管理 | 仅管理员可见：账号管理、**表单写权限 + 按钮级动作权限**（同一表单的按钮可细分给不同角色）、密码重置 |

> **已下线模块**：旧「日排产 / 生产日报」页签（函数保留不调用，数据备份）；「看板（仪表盘）」页签（`.148` 起整体移除，首屏默认页改为「订单管理」）。**字段自定义**（字段设置）现为产品主数据 / 订单内的功能，不再是独立菜单。

## 技术架构

- **零依赖**：原生 HTML + CSS + Vanilla JS，无任何框架或 CDN 引用
- **DB 异步抽象层**：`DB.get/set` 封装了 `localStorage`，预留 `API_BASE` 一行切换即可改为服务器接口
- **自研 XLSX 引擎**：纯 JS 实现 ZIP 读写 / CRC32 / DEFLATE 解压 / Excel XML 解析，零依赖导入导出 Excel
- **表格引擎**：列排序、筛选、拖拽换序、拖拽调宽、布局持久化

## 本地使用

直接用浏览器打开 `index.html` 即可，无需任何构建步骤。

## 部署到 GitHub Pages

本仓库已包含 GitHub Actions 工作流（`.github/workflows/deploy.yml`），代码推送到 `main` 分支后自动构建并发布到 GitHub Pages。

> ⚠️ **发布为显式安全白名单**：工作流只把前端运行必需的文件（`index.html`、`js/` 整个目录、`.nojekyll`）拷到临时目录 `_site/` 后发布，**不再使用 `path: .`**（那会把 `server/`、`docs/`、`backups/`、运维脚本、部署脚本等一并暴露到公网）。
> **维护约定：新增前端静态资源（新 `.html` / js 模块 / css / 图标等）时，必须同步把该文件或目录加进 `deploy.yml` 的 Stage 步骤，否则线上会 404。** 工作流内置了「必需文件缺失」与「误发布敏感内容」两道 fail-fast 校验。

1. 在 GitHub 新建一个仓库（公开或私有均可，Pages 现已支持私有仓库）
2. 推送本仓库：
   ```bash
   git remote add origin https://github.com/<你的用户名>/<仓库名>.git
   git push -u origin main
   ```
3. 仓库 **Settings → Pages**，Source 选择 **GitHub Actions**
4. 等待 Actions 运行完成，访问 `https://<你的用户名>.github.io/<仓库名>/`

## 服务器模式与安全须知

服务器模式下（`API_BASE='/api'`，见 `server/server.js`）涉及以下安全约定，运维与二次开发请务必遵循：

### 初始账号密码（.123 起不再硬编码）

首次启动（`users.json` 不存在）时自动创建 `admin` / `pmc` / `chejian` / `zongjingli` 四个账号，密码来源优先级：

1. 环境变量 `PROD_INIT_PWD` 已设置 → 所有初始账号统一使用该密码
2. 未设置 → **每个账号生成独立的 12 位随机密码**，并打印到 stdout

查看方式（systemd 服务 `prod-server`）：

```bash
journalctl -u prod-server | grep -A 10 '首次初始化'
```

新账号带 `mustChangePwd` 标记，登录后前端会提示尽快改密，`/api/change-pwd` 成功后自动清除。**首次登录后请立即修改所有账号密码。**

### 手动重置账号密码

线上存量账号若仍使用弱口令，可由运维手动重置（不启动服务，执行后退出）：

```bash
node server/server.js --reset-pwd <username> <newpassword>
```

重置后该账号会被重新置上 `mustChangePwd` 标记。

### 鉴权方式：token 走请求头

`/api/login` 成功后返回的 token 由前端放在 `Authorization: Bearer <token>` **请求头**中传递，**不再拼到 URL query**（避免写入 nginx access log / 浏览器历史 / Referer）。

服务端仍保留 query token 作为兼容兜底，可通过环境变量硬关闭：

```bash
DEPRECATE_QUERY_TOKEN=1   # 建议在旧版前端全量下线并稳定 1 周后开启
```

### 并发保存：revision 乐观锁

`/api/save` 支持可选的 `expectedRev` 字段。前端保存时会带上本地已知版本号：

- 版本号与服务器一致 → 正常写入，返回新 `rev`
- 版本号过期（他人已改过该表）→ **HTTP 409 `{ error: '数据已被他人修改', rev }`**，前端**拒绝本次保存**并提示「请刷新后重新操作」，同时自动拉取最新数据

这是为了避免**静默丢数据**（用户 B 用旧快照保存、无声覆盖用户 A 的改动）。按业务要求，冲突时**不做自动合并/自动重试**——宁可让用户重做，也不做可能算错的合并。


## 数据说明（重要）

**当前为服务器模式**：`index.html` 中 `const API_BASE='/api';`，约 10 人团队**在线共享同一份数据**，由零依赖 Node 后端（`server/server.js`，systemd 服务 `prod-server`）持久化到 `server/data.json`；前端每 5 秒轮询 `/api/revs`，版本变化即拉全量并刷新界面。

- **回退本地单机模式**：把 `API_BASE` 改为 `''` 即回退 `localStorage`（KEY 前缀 `wb_cb_prod_`）。此时数据仅存于当前浏览器、**彼此不共享**，只适合演示 / 单机调试。
- **并发写保护**：`/api/save` 带 `expectedRev` 乐观锁，版本过期返回 HTTP 409 并**拒绝本次保存**（详见上方「并发保存」），避免静默覆盖他人改动。

## 备份与恢复

- 顶部「备份」可导出全部数据为 `.json`，「恢复」可一键还原
- 自动备份：数据变更后自动下载 `.json`（最小间隔 15 分钟），换设备 / 链接轮换后用「恢复」即可还原
- 销售订单支持**金蝶导入**（.xlsx：预检报告 → 未知商品编码决策 → 幂等写入）；全量数据迁移用顶部「备份 / 恢复」（.json）
- 表单页不提供 xlsx 模板 / 手工导入（.117 起隐藏）——交付 / 排产 / 补库数据由业务动作（交付登记 / 下推生成 / 调用库存）驱动，杜绝误导入覆盖
